How I work with AI

Five rules I build by

Five rules for working with an AI agent every day — held to a higher bar here. Each one runs live in this fleet's pipeline.

Rule 1

One clear decision per batch

Don't hand the agent five fuzzy tasks. One crisp decision per work unit.

In this pipeline: the battlecard updater only touches qualifying items — one run, one job, no sprawl.

Rule 2

Hard stops are sacred

Time-box the session; when the stop hits, stop. Prevents half-done sprawl.

In this pipeline: battlecard research capped at 2–3 page reads; sessions end when they end.

Rule 3

Show, don't describe

Make the agent show the actual output — not describe what it did.

In this pipeline: the deployed-bytes rule — curl the live file before debugging a QA report.

Rule 4

Batch everything

Group similar work into one run instead of many small ones.

In this pipeline: single-commit deploys; the 06:15 / 07:15 morning production line.

Rule 5

Boring stuff compounds

Changelogs, validation scripts, checklists — the unglamorous scaffolding is what makes a daily pipeline reliable.

In this pipeline: dated CHANGELOG on every push; the midnight fleet QA.

The same thinking behind the copy-paste workflows — steal the patterns, beat the execution.
